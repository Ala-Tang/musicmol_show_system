分子 → 音乐（MIDI 事件）流程梳理

基于仓库 MusicMol_0322/app.py、分子到音乐/smile_to_midi_v10 与前端 musicmol-piano.js 的调用关系整理。

主链路：HTTP API → 服务端生成 → 前端播放

flowchart TB
  subgraph IN["输入"]
    SMILES["SMILES 字符串"]
    BPM["bpm（可选，默认 100，范围 40–240）"]
  end

  subgraph SYNC["同步接口"]
    API_MTM["POST /api/molecule_to_music
JSON: smiles, bpm"]
    RESP["响应: ok, midi_events[], meta
（canonical_smiles、event_count 等）"]
  end

  subgraph ASYNC["异步 / 联调"]
    API_SUB["POST /api/molecule_submit
可选 auto_play, session_id"]
    Q["写入待播队列 _mol_music_ui_pending"]
    POLL["GET /api/molecule_music_ui_pending
轮询"]
    DIS["POST /api/molecule_music_ui_dismiss
演奏后清除"]
  end

  subgraph SRV["服务端 app.py"]
    RD{RDKit
MolFromSmiles}
    FAIL_RD["400：无法解析"]
    GEN["_generate_midi_events_from_smiles"]
    V10["① smile_to_midi_v10
smiles_to_midi → 临时 .mid"]
    MIDO["mido 读 MIDI
note_on / note_off → 配对"]
    FAIL_GEN["500：MIDI 事件生成失败"]
    EVT["midi_events 每项:
time, type, note, duration, velocity
（毫秒 & MIDI 音高）"]
  end

  subgraph FE["前端 musicmol-piano.js"]
    NORM["normalizePlayEvent
兼容 time / start"]
    AUTO["enterAutoPlayFromMidiEvents
setTimeout 调度发声"]
  end

  SMILES --> API_MTM
  BPM --> API_MTM
  API_MTM --> RD
  API_SUB --> RD
  RD -->|失败| FAIL_RD
  RD -->|成功| GEN
  GEN --> V10
  V10 -->|成功| MIDO
  V10 -.->|异常| FAIL_GEN
  MIDO --> EVT
  EVT --> RESP
  EVT --> Q
  Q --> POLL
  POLL --> NORM
  RESP --> NORM
  NORM --> AUTO
  POLL --> DIS

就绪状态可由 GET /api/status_lite 中的 molecule_to_music 字段反映（与 分子到音乐 目录是否存在、Cython 模块是否可用等相关）。

可选分支：浏览器内 smile_to_score（未默认挂载于 index.html）

flowchart LR
  subgraph JS["smile_to_score v1 / v2 / v4 .js"]

手性 / 环 / 支链 / 键级"]
    MAP["元素 → 音名 → MIDI"]
    GSF["window.generateScoreFromSmiles
smiles, bpm"]
  end

  subgraph LEGACY["若页面引入脚本"]
    PJS["piano.js smilesToMidi()"]

  PARSE --> MAP --> GSF
  GSF --> PJS

当前主页面 index.html 主要走服务端 smile_to_midi_v10 生成的 midi_events；本地 JS 规则不一定逐字节一致，适用于离线演示或对照调试。
